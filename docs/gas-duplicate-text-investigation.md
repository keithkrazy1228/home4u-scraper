## 1. まず結論(TL;DR)

- **二重表示はデータのせいでもテンプレートのせいでもない。GASの「書き込み処理」が原因**。
  DBスプレッドシートとテンプレートスライドの両方を実際に読み、どちらも正常なことを確認済み。
- **二重になるのは「GASが書き込む項目の一部だけ」**。同じスライド上でも、
  正常な項目(調査技師名など)と二重の項目(責任者名など)が混在している。
  → 書き込みルートが2系統あり、片方のルートだけが「2回書いている」。
- **GASのコード本体は毎日GitHubに自動バックアップされている**ことを発見した
  (`keithkrazy1228/a2g-gas-system-registry` の `projects/03_A2G_雨漏り調査報告書自動生成__1T7EkbXs/`)。
  ただし現在のClaudeセッションにはこのプライベートリポジトリへのアクセス権が無く、
  **原因行の特定はここで一時停止**。アクセス許可(後述の次の一手A)をもらえれば即再開できる。

### 2-2. データは正常(=犯人ではない)

DBスプレッドシートを直接読んだ結果:

- 案件 `fc74628b`(テストサロン): 顧客名は **「テスト」単体**。「テストテスト」ではない。
- 担当営業は調査員ID `59d2c725` 等で参照され、調査員マスタは
  **「冨田佳佑」「山下隼也」「小俣辰也」すべて単体**で正常。
- 総合所見の本文もDB上は1回分のみ。

**例え話**: 印刷屋さん(GAS)に渡した原稿(DB)は1部だけ。刷り上がりが2部重なっているなら、
悪いのは原稿ではなく印刷機の動きです。

### 2-3. テンプレートも正常(=犯人ではない)

テンプレート【修正版】全19枚を読んだ結果:

- 二重テキストは1か所もない。
- `{{顧客名}}` のようなプレースホルダー方式では**なく**、
  「佐藤 太郎 様」「本田」「小俣」といった**サンプル文がそのまま入っている方式**。
  → つまりGASは `replaceAllText` でトークン置換しているのではなく、
  シェイプを特定して中身を書き換える方式の可能性が高い(コードで要確認)。
- フッターのページ番号「1 / 19」〜「19 / 19」はテンプレート上に**固定文字**として存在する。

### 2-4. 生成されたスライドの二重パターン(スライド「うぇええ_テスト_テストサロン_...20260820」全18枚を解析)

テキスト抽出の結果、二重には**2種類の形**がある:

**(A) 1つのテキストボックスの中で文字列が2回連結されている**(主パターン)
- フッター: `1 / 191 / 19`(= "1 / 19" + "1 / 19"。全ページ)
- 依頼主: `テスト様テスト様`(DBは「テスト」→ GASが「テスト様」を作り、それが2回)
- 責任者: `冨田冨田` `山下隼也山下隼也` `小俣辰也小俣辰也`
- サマリーの結論ラベル: `今回の結論今回の結論`
- サマリー本文: 結論2文のかたまりが丸ごと2回(2回目の先頭が1回目の末尾と同じ行に連結
  → 改行を挟まず「本文+本文」を連結した形。2枚のボックス重なりではこうならない)
- キャプション: `調査対象|1階サッシ/1階お風呂` が1行内で2連続

**(B) シェイプ(テキストボックス)自体が2組挿入されている**
- スライド4の検収印: テンプレートでは空欄なのに、生成後は
  `冨田/山下/小俣` の3ボックスが**2セット(計6個)**存在する。

**重要な対照**: 同じスライド4で、
- 二重: 営業責任者・調査責任者・施工責任者(=責任者ブロック)、検収印
- 正常: 調査技師「冨田佳佑」、調査監修、調査開始日・完了日、物件名、所在地、用途 など

→ 「全部が2回」ではない。**特定の書き込みルートを通った項目だけが2回**書かれている。

### 2-5. バグ3(ページ数不一致)の観測事実

- テンプレートは19枚。生成スライドは18枚(=どこかで1枚削除している。
  消えたのは「13|建物診断・写真続き」に相当するページ)。
- ページ番号の刷り直しが**途中まで**行われている:
  総合所見は「17 / 19」に振り直し済みだが、最終ページ(注意事項)は「19 / 19」のまま。
  「18」というページ番号のスライドが存在しない。
- 分母「19」はテンプレートの枚数のまま。
  → **ページ番号の書き込みと不要ページの削除の実行順序に矛盾がある**
  (番号を振った後にページを消している、または分母を削除前の枚数で計算している)。
  PDFが19ページある点も含め、正確な因果はコードで確認する。

### 2-6. バグ2(見切れ)の観測事実

- 「撮影場所:あなた」は写真1枚目のみ全文表示、2枚目以降は「撮影場所:あな」。
- 「あな」は2文字ちょうどで切れており、枠幅による視覚的な見切れではなく
  **文字数での切り詰め処理**の可能性がある(未確定・コードで要確認)。

## 3. 仮説(コードを読むまで断定しない)

引き継ぎ書の推定原因(a)(b)(c)に対する現時点の評価:

- (a) 影用テキストボックス2枚重ね → **主原因としては否定寄り**。
  重なりなら抽出結果が2行に分かれるはずだが、主パターンは1ボックス内の連結(2-4-A)。
  ただし検収印(2-4-B)はシェイプ2組なので、挿入系の処理は2回走っている。
- (b) replaceAllTextとinsertTextBoxの二重挿入 → **半分否定**。
  テンプレートにプレースホルダーが無いためreplaceAllText主体の設計ではなさそう。
- (c) 生成処理が2回実行 → **有力(ただし「全体が2回」ではなく特定ルートのみ)**。
  正常項目が存在するため、「setText(置換)ルートは2回走っても同じ結果(冪等)、
  appendText/insertText(追記)ルートは2回走ると二重になる」という説明が
  観測結果と最も整合する。呼び出し側のループ重複か、追記ヘルパーの二重呼び出しが疑わしい。

**コードで確認すべき箇所**(pullできたら最初にgrepする):
`appendText` / `insertText` / `insertTextBox` / `setText` / `asRenderedString` /
ページ番号スタンプ処理 / スライド削除処理(`remove()`) / 責任者・検収印の書き込み関数 /
`substring`・`slice`(バグ2の切り詰め)

## 4. ブロッカーと次の一手

コード本体に到達するルートが現在すべて塞がっている:

1. このリポジトリ(home4u-scraper)にGASコードは無い
2. コンテナバインド型GASはDrive API経由で読めない(スタンドアロン型のみ可)
3. バックアップ先 `a2g-gas-system-registry` はプライベートで、
   ClaudeのGitHub連携に未登録(アクセス拒否を実測で確認)
4. clasp はGoogleアカウントの対話ログインが必要で、リモート自動セッションでは実行不可

### 次の一手(どちらか一方でOK)

**A. (推奨・約2分)GitHub連携にバックアップリポジトリを追加する**
claude.ai の GitHub設定(組織管理者なら https://claude.ai/admin-settings/claude-tag 、
個人連携なら Settings → Connectors → GitHub)で
`keithkrazy1228/a2g-gas-system-registry` へのアクセスを許可する。
→ 許可後にClaudeへ「続きをやって」と伝えれば、コードを読んで原因行を特定し、
修正案の提示まで一気に進められる。**毎日の自動バックアップがそのまま「コード閲覧窓口」になる**ので、
今後の改修でも一番ラクな道。

**B. 手元のPCで clasp を使ってコードを取り出す**(Aが難しい場合)
```bash
npm install -g @google/clasp   # claspという「GASをPCに持ってくる道具」を入れる
clasp login                    # ブラウザが開くのでGoogleアカウントで許可する
```

取り出した `.gs` ファイル一式をこのリポジトリに追加してpushするか、チャットに貼る。
